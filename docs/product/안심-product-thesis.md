# 제품 정의서 — "안심" 투자 동반자

> 작성일 2026-06-02 · 브레인스토밍 세션 캡처본 · 1차 결정 문서(확정 아님, 검증 대상 포함)

---

## 1. 한 줄 정의

**더 벌어주는 앱이 아니라, 덜 잃고 덜 불안하게 해주는 앱.**
Buy & Hold를 "수익률"이 아니라 "경험"으로 이긴다 — 즉 큰 낙폭과 패닉 셀(공포 매도)을 막아준다.

## 2. 타겟 — "불안한 장기보유자"

- 규율 잡힌 진짜 장기투자자(우리가 필요 없음)도, 단타족(우리가 거부함)도 아님.
- **길게 들고 가긴 하지만 매 하락마다 손에 땀 쥐며 괴로워하는 사람.** 크고, 아무도 안 섬기는 세그먼트.

## 3. 절대 안 하는 것 (Non-goals)

- ❌ "사라/팔아라/목표가" 같은 **투자 권유·조언** (법적 + 신뢰 지뢰)
- ❌ **매일 열게 만들기** — 매일 주식창 열기 = 단타 습관 = 우리가 구하려는 그 병
- ❌ **"안전합니다" 단언** — 거짓 음성 한 번에 즉사. 항상 "○/○ 기준" 형태로 시점 자백
- ❌ **예측을 안심의 근거로 사용** (4번 참조)
- ❌ 빈 ChatGPT식 채팅창 (단타 oracle·강박 루프로 변질)

## 4. 검증된 사실 — 모델은 낙폭을 못 본다 (perma-bull)

기존 backtest 로그(QQQ, 549행, 2023-09~2025-12) 분석 결과:

- 실제 하락한 날 중 모델이 하락 예측: **15.3%** (3% 이상 큰 하락은 **8%**만 포착)
- -11~-15% 폭락 직전, 모델은 거의 전부 **+0.8~+1.5% 상승** 예측 (2024-08, 2025-03~04 전부 놓침)
- 방향 정확도 68% < "무조건 상승" 베이스라인 76% → **하방 감지기로서 가치 음수**
- 예측 하방 한계 -1.79% → 큰 하락을 **표현할 능력 자체가 없음**

**결론: 예측 모델을 안심·공포 트리거의 근거로 쓰면 "폭락 직전 잘못된 안심"을 주는 앱이 됨.**
→ 제품 코어를 **예측이 아니라 사실 + 과거 통계(base rate)** 위에 짓는다.

## 5. 핵심 구조

| 레이어 | 내용 | 근거 |
|---|---|---|
| **위젯/알림 (평소 95%)** | "안 열어도 안심" 전달. B형 기록("52일째 조용") + 상태등 + 날짜 정직성 | 뱅크샐러드 "알림=가치" 원리 |
| **앱 메인** | 정적 + heartbeat("지켜보는 중") — 침묵이 방치 아닌 능동 감시로 읽히게 | 홈 보안 패널 모델 |
| **리듬** | 매일 X, **주 1회 의식** | 장기투자 철학 정합 |
| **진입 트리거** | 우리가 만들지 않음. **시장이 무서운 날 = 실현 낙폭**(예측 아님) | 뱅크샐러드 "월말 쪼들림" |
| **승부처: 공포의 순간 화면** | 패닉 셀 방지. 진정시키기(↑안심), 경고로 공포 증폭 금지 | B&H를 이기는 실제 메커니즘 |

상태는 3단계: **평온(🟢) / 주시(🟡) / 확인(🔴)**.

## 6. LLM = "통역가", 조언가 아님

**핵심 규정: LLM은 새 주장을 만들지 않는다. 화면에 이미 있는 사실을 사용자의 언어로 번역한다.**
→ grounding 보장 + 환각 최소화 + 고장난 예측 모델에 비의존.

활용 형태 (안전·가치 순):
1. **"이게 무슨 뜻?"** — 화면의 사실(집중도·변동성·낙폭) 옆 번역 버튼. 위험 0, 어디에나.
2. **공포의 순간 진정 플로우** — 실현 낙폭 트리거 → 상황 미리 채움 → 탭형 불안 질문 3~4개 → **과거 base rate + 보유 종목**으로 답 → "결정은 당신 몫"으로 끝.
3. 주간 대화형 브리핑 / 4. 회고("안 팔았고 그게 옳았어요" = 신뢰 적립)

**등장 시점:** 공포의 순간 + 주간 점검만 (상시 X → 강박 루프 방지).
**가드레일:** "모델/과거 기준" 액자화, 종목추천·예측확장 금지, 최종 결정은 사용자.

## 7. 아키텍처 — 붙이기는 additive (UI 안 뒤엎음)

- **data-ml(ML): 0 변경.** 오프라인 학습 파이프라인일 뿐, 서버·LLM 없음.
- **백엔드: 추가만.** `ThemeSignalNarrativeCache` 주석 = "LLM 호출은 백엔드 담당, iOS는 텍스트만 수신". **LLM→텍스트 파이프라인 이미 존재.** 대화 엔드포인트만 확장.
- **iOS: 추가만.** 깨끗한 Repository 패턴(Protocol + Live/Mock + Factory). 챗 = 새 Repository + ViewModel + 시트. 기존 화면 안 건드림.
- ⚠️ 구분: *LLM 챗 = additive* vs *예측 중심 UI(TOP3 등) 철거 = 별개의 전략 피벗* (모델 발견 때문에 어차피 해야 함).

신규 백엔드 작업: ①대화 엔드포인트(멀티턴·실시간) ②base-rate 히스토리 grounding 데이터(사실/백테스트, 안전) ③실시간 호출 비용·지연.

## 8. 빌드 순서

1. **예측 중심 UI 철거** (TOP3 등) — 모델이 못 받치므로
2. **① "이게 무슨 뜻?" 번역 버튼** — 기존 내러티브 패턴 재사용, 위험 0
3. **위젯/알림 안심 레이어** (기록 + 상태등 + 날짜 정직성)
4. **② 공포의 순간 챗** — base-rate grounding + 멀티턴

## 9. 파킹 / 검증할 가정

**파킹:** 모델 낙폭예측 개선 (추후 ML 과제, 5일 크래시 예측은 본질적으로 어려움 — 제품을 여기 걸지 않음).

**아직 미검증, 싼 순서대로 테스트:**
1. **D+5 일별 예측 로그 복구 후 같은 perma-bull 테스트** (현재 production 예측 스트림이 repo에 없음 = 위젯 heartbeat·드리프트 모니터링의 엔지니어링 전제)
2. **"불안한 장기보유자" 3~5명 인터뷰** — 하락장에서 실제로 뭘 하고/검색하고/누구한테 묻나? 공포의 순간 행동이 가설대로인가
3. **"열지 마세요" 모델의 사업성** — 잊혀진 앱 사망 위험 vs 신뢰 잔고. 위젯 존재감 + 관계 유지로 충분한가
4. **패닉 셀 방지 효과 측정 가능성** — 안 일어난 매도를 어떻게 증명하나(KPI 설계)
