## 1. 핵심 차별점 — 한 줄

**Yahoo Finance처럼 종목 관련 뉴스를 나열하는 탭이 아니다.** 내가 보유한 자산 조합을 이해하고, 그 조합 기준으로 걸러내고 종합한 하나의 브리핑을 준다.

차별화 지점 두 가지:
1. 보유 자산 24시간 뉴스를 필터링 → Haiku가 여러 기사를 하나의 요약 + 헤드라인으로 종합 (기사 나열이 아니라 종합)
2. 여러 보유 종목에 공통으로 영향을 주는 이슈(관세, 금리 등)를 감지해 상단에 예외적으로 배치 — "내 포트폴리오 전체에 무슨 일이 있었나"에 답하는 구조

## 2. 데이터 파이프라인

### 2.1 수집

- yfinance로 **보유 자산별** 24시간 이내 뉴스 필터링·수집
- 생성 주기는 실시간이 아니라 **배치 — §5 참조**

### 2.2 공통(매크로) 이슈 감지

종목별로 수집한 뉴스 목록에서, **같은 뉴스(uuid)가 보유 종목 2개 이상의 피드에 겹쳐 나오면** "포트폴리오 전반에 영향을 주는 이슈"로 판단해 상단 배너로 승격한다.

```
종목별 24h 뉴스 수집 (uuid 포함)
   ↓
종목 간 uuid 교집합 확인
   ↓
2개 이상 종목에 겹치는 uuid → 매크로 배너 후보로 분리, 개별 종목 요약에서는 제외
   ↓
겹치지 않는 나머지 → 종목 셀 요약 대상
```

- 이 방식은 추가 API 호출이나 LLM 분류 없이, 이미 계획된 종목별 수집 결과의 **후처리 dedup만으로** 성립한다.
- **알려진 한계 (v1에서 감수):** 같은 사건을 다른 매체가 다른 기사(다른 uuid)로 보도한 경우는 못 잡는다. 근사 중복(제목 유사도, 또는 LLM 판별) 클러스터링은 v2 과제로 파킹.
- **겹침 문턱값은 잠정 2개.** 확정치가 아니라 v1 출발점 — §8 참조.
- 보유 종목이 1~2개뿐인 사용자는 구조적으로 이 배너가 거의 안 뜬다. 이건 버그가 아니라 자연스러운 축소다 — 종목이 1개면 그 종목 뉴스가 이미 정의상 "포트폴리오 전체 영향"이므로 구분 자체가 무의미해진다.

### 2.3 요약 생성 (Haiku)

종목당 **Haiku 호출 1회**로 헤드라인·소제목·요약 본문·AI 판단 문장을 구조화된 JSON으로 한 번에 생성한다.

```json
{
  "ticker": "NVDA",
  "headline": "여러 기사를 아우르는 헤드라인 1개",
  "subheadline": "리스트 셀용 한 줄 소제목",
  "summary": "상세 화면용 요약 본문 (2~4문장)",
  "new_facts": ["숫자·날짜 등 구체적 사실 위주 2~4개, 새로운 게 없으면 빈 배열"],
  "ai_view": "전망/변동성에 대한 정성적 코멘트 (수익률·매수매도 신호 없음)",
  "sources": [{ "title": "…", "source": "…", "publishedAt": "…", "url": "…" }]
}
```

**헤드라인 생성 방식 — 클러스터링 알고리즘 대신 프롬프트 판단.** 한 종목에 기사가 여러 개 쌓였을 때:
- 하나의 사건을 여러 매체가 다룬 경우 → 통합 헤드라인
- 서로 다른 사건이 같은 날 겹친 경우(실적+리콜+CEO 이슈 등) → 다이제스트형 헤드라인 ("테슬라, 실적 호조 속 리콜 이슈도 부각")
- 이 판단 자체를 Haiku 프롬프트에 맡긴다. 별도 클러스터링 로직은 만들지 않는다 (검증 안 된 복잡도를 미리 만들지 않는다는 원칙 — §7 매크로 배너 논의에서도 동일하게 적용).

**전처리 (Haiku 호출 전 필수):**
- 종목당 기사 개수 상한 설정 (제목 유사도 기반 근사 중복 제거 후 상위 N개, 8~10개 선)
- 기사량 폭주 시(실적일 등) 중복 기사가 헤드라인을 편향시키지 않도록 함

**헤드라인·요약 톤 가드레일:**
- 원본 기사에 없는 숫자 금지
- 선정적 동사 금지 (폭등, 폭락, 급등, 충격 등)
- 방향 예측·매수매도 권유 문구 금지 ("오를 것으로 보입니다", "지금 사세요" 등)
- "안전합니다" 류의 단정 금지 — 항상 시점 자백 형태
- 긴급성 조작 문구 금지 ("놓치지 마세요", "지금 확인하세요")
- `new_facts`는 숫자·날짜·고유명사 등 구체적 사실만. 헤드라인 재진술이나 근거 기사에 없는 디테일 채워넣기(패딩) 금지 — 새로 알려진 게 없으면 빈 배열로 둔다.

### 2.4 캐싱

**종목 단위 캐싱 — 사용자 단위 아님.** 대부분 사용자가 겹치는 종목(AAPL, TSLA 등)을 들고 있으므로, 종목별 요약을 하루 1회 생성해 캐시하면 Haiku 호출량이 사용자 수와 무관해진다. 사용자별로는 보유 종목 조합에 맞춰 캐시된 요약을 조립만 한다.

### 2.5 yfinance 리스크 대응

yfinance는 비공식 스크레이퍼라 두 가지 리스크가 있다: **라이선스 리스크**(Yahoo 이용약관상 상용 재배포 회색지대)와 **안정성 리스크**(SLA 없음, 페이지 구조 변경 시 예고 없이 깨짐).

1. **소스 레이어 추상화.** `NewsSourceProvider` 프로토콜을 두고 `YFinanceNewsProvider`(v1 프로토타입)와 향후 `LicensedNewsAPIProvider`(Finnhub, Polygon.io, Alpha Vantage News 등 후보)가 같은 인터페이스를 구현하도록 설계. 나중에 정식 API로 교체할 때 파이프라인을 다시 짜지 않고 프로바이더만 교체한다.
   - 프로바이더 평가 기준에 **썸네일 제공 여부**를 포함 — §4.0 대표 이미지 로직과 직결됨.
2. **종목 단위 수집 실패 → 조용 상태로 흡수.** 특정 종목 수집이 실패해도 에러를 노출하지 않고 §6의 조용 로우("N일째 특이사항 없음")로 처리. 사용자 입장에서 "수집 실패"와 "진짜 조용한 날"을 구분할 필요가 없다는 원칙에 근거.
3. **전체 배치 실패 → 캐시 + 오프라인 표기.** yfinance가 그날 전체적으로 막히는 경우는 다르게 처리한다 — 캐시된 이전 데이터를 보여주고 "○일 ○시 기준 (오프라인)" 표기.
4. 원문 전체 대신 헤드라인+스니펫 기반 요약 + 출처 링크 명시는 기존 원칙 유지 (§2.3 톤 가드레일과 함께 라이선스 리스크 완화).

### 2.6 모델 기반 섹터 신호 (예정 — 팀원 모델 완성 후 연동)

현재 QQQ 한정으로 검증된 LSTM(이벤트 감지, T+2 ±2% 이상 변동) + XGBoost(방향 분류) 조합 모델이, 산업 대표 섹터 ETF 위주로 확장 중이다(개별 종목보다 예측이 상대적으로 쉬움). 아직 미완성 — 완성 후 아래 방식으로 연동한다.

- **모델 신호는 종목별 AI판단이 아니라 매크로 배너로 라우팅한다.** 사용자가 보유한 건 대부분 섹터 ETF 자체가 아니라 개별 종목이므로, 섹터 모델의 신호를 특정 종목에 그대로 얹으면 정확도 오버클레임이 된다 — 섹터 전체 흐름과 개별 종목의 움직임은 갈릴 수 있다.
- **필요 매핑: 종목 → 섹터.** 예: NVDA→반도체. 보유 종목과 섹터 신호를 연결하려면 이 매핑이 필요하다. 구현 방식(GICS, yfinance sector 필드 등)은 미정 — §8.
- **등급 게이팅 재사용.** 기존 LSTM/XGB 플로우의 Normal / High Confidence / Strong 등급 체계를 그대로 써서 매크로 배너 노출 문턱을 정한다. 구체적으로 몇 등급부터 노출할지는 미정 — §8.
- **매크로 배너 소스가 이제 2가지.** ① 뉴스 uuid 겹침 감지(§2.2, 구현 대상) ② 모델 섹터 신호(이 섹션, 예정 — 팀원 모델 완성 후). 두 소스가 같은 배너 슬롯을 공유하되 로직은 독립적이다.

## 3. 정보구조 — 뉴스룸 리스트

```
[뉴스룸 리스트]
  │
  ├─ 매크로 배너 (겹침 이슈 있을 때만, 없으면 섹션째 숨김)
  │
  └─ 종목 셀 목록 (보유 종목 단위)
       ├─ 뉴스 있음 → 헤드라인 + 소제목 + (가능하면 이미지)
       └─ 뉴스 없음 → 조용 상태 표시 (§6)
```

### 3.1 매크로 배너

- **"예외적 배너"로 포지셔�다.** 상시 존재하는 구역이 아니다.
- 겹침 이슈가 없는 날엔 **완전히 숨김.** "오늘은 이슈가 없어요" 같은 placeholder도 넣지 않는다 — placeholder 자체가 "여기 뭔가 있어야 하는데 없다"는 인상을 줘서 예외 프레임을 깨기 때문.
- v1은 별도의 baseline 매크로 뉴스 소스(예: 종목 안 걸린 일반 시장 뉴스)를 미리 만들지 않는다. 겹침 감지만으로 출시하고, 실제 트리거 빈도를 로그로 관찰한 뒤 필요성이 확인되면 그때 추가.

### 3.2 종목 셀

- 셀 단위는 **종목(자산) 단위**로 확정.
- 뉴스 있는 종목: 헤드라인 + 소제목 구성 (WSJ Top Stories 참고).
- **히어로/컴팩트는 같은 Haiku 호출의 headline/subheadline을 그대로 재사용한다 — 별도 생성 없음.** 히어로는 headline(크게)+subheadline(작게) 둘 다 노출, 컴팩트는 공간이 좁으므로 subheadline 한 줄만. (카테고리+건수 형태의 별도 요약 문구는 안 만든다 — 추가 필드·분류 로직 없이 기존 스키마로 해결)
- **이미지: 종목 로고/아이콘을 셀 앞에 작게 배치. 크기를 키우지 않는다.**
  - 가격 스파크라인은 채택 안 함 — 여러 셀에 걸쳐 노출되면 "시세 스캔" 습관을 유도해 상위 문서의 패닉셀 방지·재방문 유도 금지 철학과 부딪힘. §7.1에서 이미 등락률을 텍스트로 보여주기로 했으므로 시각적으로 한 번 더 반복하는 것도 불필요.
  - 기사 썸네일도 채택 안 함 — yfinance 썸네일 유무가 들쭉날쭉하고, 우산 제목이 여러 기사를 합친 것이라 "어느 기사 사진을 대표로 쓸지" 편향 문제가 생김.
  - 로고/아이콘은 매번 동일해 저작권 리스크가 적고, 대표성 문제도 없으며, 순수 텍스트보다 스캔이 쉬움.
- 정렬 순서 및 카드 티어링: §3.3.

### 3.3 정렬 순서 & 카드 티어링

**정렬 키(2단계):** ① hasNews 여부(있음이 먼저) → ② 보유 비중 내림차순. 같은 비중이면 최신 기사 시각 순.

```python
sorted_holdings = sorted(
    holdings,
    key=lambda h: (not h.has_news, -h.portfolio_weight)
)
```

**카드 티어링:** hasNews 그룹 안에서 **보유 비중 상위 2개**만 히어로 카드, 나머지는 컴팩트 로우. 조용 그룹(hasNews=false)은 전부 조용 로우(§6)로, 티어 구분 없음.

```
┌ 뉴스룸 ──────────────────────────────┐
│ 7월 18일 06:00 기준 · 다음 업데이트는  │
│ 내일 아침이에요                       │
├────────────────────────────────────┤
│ [매크로 배너] (있을 때만)              │
├────────────────────────────────────┤
│ ★ 히어로 카드 — 비중 1위 (뉴스 있음)   │
│ ★ 히어로 카드 — 비중 2위 (뉴스 있음)   │
│ ─ 컴팩트 로우 — 비중 3위 (뉴스 있음)   │
│ ─ 컴팩트 로우 — 비중 5위 (뉴스 있음)   │
│  … 뉴스 있는 나머지 종목, 비중순       │
├────────────────────────────────────┤
│ 조용 로우 — 비중 4위 (뉴스 없음)       │
│ 조용 로우 — 비중 6위 (뉴스 없음)       │
│  … 나머지 종목                       │
└────────────────────────────────────┘
```

**왜 hasNews를 1차 키로 두는가.** 순수 비중순만 쓰면 매일 같은 종목이 맨 위에 고정돼 "매일 똑같은 뉴스룸"이 될 위험이 있음. hasNews를 1차 키로 두면 뉴스 있는 종목만 상단 그룹에 모이고, 그날 어떤 종목에 뉴스가 있었는지에 따라 상단 그룹 구성 자체가 매일 바뀐다. "보유 비중 우선"은 각 그룹 *내부* 정렬 기준으로 반영.

**히어로 캡을 2개로 둔 이유.** 보유 종목 11개 기준 설계. 뉴스 있는 날 전부 히어로로 띄우면 스크롤이 길어지고 "유한한 브리핑" 감각이 깨짐. 상위 2개만 크게, 나머진 컴팩트로 눌러 화면 길이를 통제.

**트레이드오프.** 비중은 작지만(예: 3%) 뉴스 중요도가 큰 종목은 이 규칙상 히어로가 못 됨. 지금은 단일 신호(비중)로 단순하게 가는 쪽을 택함. 나중에 "뉴스 중요도"를 히어로 승격의 추가 조건으로 넣을지는 재검토 여지로 남겨둠.

**스케일 노트 — 보유 종목이 20개 이상으로 늘어나면 재검토.** 조용 로우를 전부 개별 나열하면 리스트가 길어져 "유한한 브리핑" 느낌이 깨짐. 이 경우 "나머지 N개 종목은 특이사항 없음" 한 줄로 접는 방식을 고려.

### 3.4 리스트 화면 상태

리스트는 네트워크 왕복이 있는 유일한 화면이다 (§4.3 참조 — 상세는 별도 로딩이 없다). 상태는 4가지.

| 상태 | 트리거 | 화면 |
|---|---|---|
| 최초 로딩 | 데이터 도착 전 | 스켈레톤 (섹션 구조를 유지한 채 회색 블록) |
| 로드 실패 (캐시 없음) | 첫 로드 자체가 실패 | "불러오지 못했어요" + 재시도 버튼. §2.5의 "전체 배치 실패(캐시 있음, 오프라인 표기)"와는 다른 케이스 — 이건 캐시조차 없는 경우 |
| 보유 종목 0개 | 자산 미등록 | "아직 등록된 자산이 없어요" + 자산 등록 CTA |
| 온보딩 · 첫 생성 중 | 방금 첫 자산 등록, §5.1의 온디맨드 생성 진행 중 | "첫 브리핑을 준비하고 있어요" + 보유 종목 수 언급 |

에러·온보딩 상태는 같은 골격(아이콘 + 헤드라인 + 서브텍스트 [+ 버튼])을 재사용하되 아이콘·문구·버튼 유무로 구분한다.

### 3.5 마이크로 인터랙션 — 리스트

- **탭 재진입:** 스크롤 최상단으로. **배지·빨간 점은 절대 사용 안 함** — 재방문 유도 금지 원칙(§5) 그대로 적용.
- **매크로 배너 등장:** 펄스·바운스·슬라이드 등 강조 애니메이션 없음. 다른 카드와 동일하게 화면 로드 시 정적으로 존재 — "공포 증폭 금지" 원칙의 연장.
- **햅틱:** pull-to-refresh 결과 실제로 새 콘텐츠가 있을 때만 가벼운 햅틱. 그 외(매크로 배너 등장 포함)는 전부 무햅틱.
- **Pull-to-refresh:** §5 원칙대로 LLM 파이프라인을 트리거하지 않고 캐시 확인만. 대부분 "이미 최신이에요" 토스트로 끝남 — 이게 고장난 것처럼 느껴지지 않도록 카피가 중요.

### 3.6 리스트 종료 마커

리스트 맨 아래, 조용 로우까지 다 보여준 후 **"오늘 브리핑은 여기까지예요"** 한 줄로 마무리한다. "더 보기", 추천, 무한 로딩 없음 — 콘텐츠가 유한하다는 것 자체가 §5의 "매일 열 이유를 만들지 않는다" 원칙을 시각적으로 증명하는 장치다. (실제 화면에 이미 존재 — 새 스펙에 누락돼 있던 것을 확인 후 반영)

## 4. 상세 화면 구성

사용자가 셀을 탭했을 때:

```
① 종목 헤더 — 티커·오늘 등락 + 자산 영향 환산 — §7.1
② 제목 (헤드라인)
③ 대표 이미지 — §4.0
④ 'AI는 이렇게 판단했어요' 섹션 — §4.1
⑤ Haiku 요약 본문 + 새로 알려진 내용 — §4.2
⑥ 소스 출처 목록
```

> **순서 수정 메모 (목업 작업 중 발견):** §7.1은 자산 영향 환산이 "상세 화면 최상단"에 노출돼야 한다고 명시하는데, 최초 초안은 헤드라인을 먼저 두는 실수가 있었다. 종목 헤더(가격+자산영향)를 최상단으로 수정 — 사용자가 헤드라인을 읽기 전에 "이게 내 얘기"라는 걸 먼저 확인시켜주는 게 개인화 차별점을 가장 먼저 증명하는 방식이라서다.

### 4.0 대표 이미지

리스트 셀과 달리 상세 화면은 사용자가 이미 이 뉴스를 읽기로 결정한 뒤이므로, 리스트에서 우려했던 "시세 스캔 습관" 문제가 적용되지 않는다. 다만 여러 기사를 합친 요약에서 어느 사진을 쓸지는 여전히 결정이 필요하다.

- **대표 기사(가장 많이 인용됐거나 가장 최신인 기사)의 yfinance 썸네일을 사용**, "사진: [출처명]" 형태로 귀속 명시.
- 헤드라인 가드레일의 귀속 표기 원칙과 일관됨. 하단 소스 출처 목록(⑥)이 있어 "여러 기사 중 하나의 사진"이라는 맥락이 자연스럽게 드러남.
- **폴백:** 그날 수집된 기사에 썸네일이 하나도 없으면, 이미지 영역과 동일한 크기의 박스 안에 종목 로고(크게)+회사명 텍스트를 중앙 정렬해 표시. 썸네일 유무와 무관하게 레이아웃 높이가 일정하게 유지되도록 — 화면이 비어 보이거나 상태에 따라 레이아웃이 들쭉날쭉해지는 것 방지. (실제 화면 확인 결과 반영)
- **이미지 영역 높이: 150pt.** 원래 190pt였으나, 디자인 크리틱에서 폴백 상태(로고+회사명만)의 정보 밀도 대비 공간이 과하다는 지적 후 축소. 실제 사진이 있는 경우에도 동일하게 적용.
- AI 생성 일러스트는 채택 안 함 — 파이프라인·비용이 늘고, 사실과 안 맞는 그림이 나오면 신뢰를 깎아먹을 리스크가 큼.

### 4.1 'AI는 이렇게 판단했어요' 섹션

- 위치: 제목 바로 아래.
- 내용: **전망·변동성 같은 추상적·정성적 코멘트만.** 향후 수익률, 매수/매도 신호처럼 명확한 판단은 리스크가 크므로 배제.
- **가장 가치 있는 순간 — 뉴스 톤과 모델 신호가 상충할 때.** 예: 뉴스는 긍정적인데 변동성 확대 신호가 있는 경우, "뉴스 분위기는 긍정적이지만 데이터상 변동성이 커지는 구간입니다" 같은 문장이 이 섹션의 존재 이유를 증명한다. 뉴스만 봐서는 안 보이는 걸 보여주는 게 이 섹션의 역할.
- 확률·수치를 직접 노출하지 않는다 (앵커링·공포 유발 방지). 정성적 문구로만 표현.
- 면책 고지 필요: "본 내용은 투자 판단의 근거가 아닙니다" 류.

**등장 애니메이션 — 1회성만, 실시간 생성처럼 보이지 않게.** 화면 진입 시 섹션 전체가 살짝 페이드인(0.25초)하고, 아이콘이 스케일 팝으로 한 번만 나타난다.

- **타자기 효과(한 글자씩 텍스트가 써지는 연출)는 채택 안 함.** 이 요약은 전날 배치로 이미 생성돼 캐시된 것인데(§5), 타자기 효과는 "지금 실시간으로 생성 중"이라는 인상을 줘서 §5의 날짜 정직성 원칙과 충돌한다.
- **아이콘 반짝임은 루프가 아니라 1회성.** 반복 애니메이션은 시선을 계속 붙잡아두는 인게이지먼트 장치라 §3.5의 "주목 유도 모션 금지" 원칙과 부딪힌다. 한 번 재생되고 정지 상태로 남는다.

**섹터 신호 참고 문맥 (예정 — §2.6 모델 완성 후).** 개별 종목 AI판단은 기본적으로 순수 뉴스 해석을 유지한다. 다만 그 종목이 속한 섹터에 활성 모델 신호가 있으면 한 줄만 "참고 문맥"으로 추가한다.

- 예: "참고로 반도체 섹터 전반에 변동성 신호가 있어요(모델 기준)."
- **항상 섹터 단위로 귀속 — 절대 "이 종목"으로 안 읽히게.** 섹터 모델의 정확도를 개별 종목에 몰래 얹지 않는다.
- 매크로 배너와 문구를 복제하지 않는다 — 같은 정보를 두 번 반복하면 피로감만 커진다는 원칙(§2.2)을 여기도 적용.
- 구현: 종목별 Haiku 호출(§2.3) 입력에 "이 종목 섹터의 활성 모델 신호 여부"를 추가 입력으로 넣는다. 신호 없는 대다수 종목은 지금 설계 그대로 (순수 뉴스 해석).

### 4.2 요약 본문 & 새로 알려진 내용

Haiku 요약(`summary`)은 리드 문단처럼 자연스럽게 읽히는 2~4문장. 그 아래 **"새로 알려진 내용"** 소제목으로 `new_facts` bullet 2~4개를 붙인다.

- 문단은 흐름(맥락)을, bullet은 구체적 사실(숫자·날짜·고유명사)을 담당 — 역할을 분리해서 "정보량이 부족해 보인다"는 문제를 해결.
- bullet은 절대 패딩하지 않는다. 근거 기사에 실제로 있는 새 사실만, 없으면 섹션 자체를 생략(빈 배열).
- 소제목은 질문형이 아닌 명사형("새로 알려진 내용") — 화면 전체가 질문-답 형식으로 읽히지 않게.

### 4.3 로딩 상태 없음 (아키텍처 근거)

상세 화면은 별도 네트워크 요청을 하지 않는다. 리스트를 불러올 때 종목별 전체 다이제스트(헤드라인부터 소스 목록까지)를 한 번에 받아오므로, 셀 탭은 로컬 네비게이션일 뿐이다 — 리스트가 로드됐다면 상세도 이미 준비돼 있다.

유일한 예외적 실패 지점은 하단 소스 기사 링크(인앱 브라우저)가 깨진 경우. 이건 화면 상태가 아니라 인터랙션 실패로 가볍게 처리한다 (인앱 브라우저 자체의 기본 에러 화면에 위임, 별도 커스텀 UI 불필요).

### 4.4 소스 기사 인터랙션

소스 출처 목록의 기사를 탭하면 **인앱 브라우저(시트)**로 연다 — 외부 브라우저로 나가면 앱 컨텍스트를 잃으므로, 뒤로가기 한 번으로 복귀 가능한 인앱 브라우저가 낫다.

## 5. 업데이트 주기 (기존 문서에서 유지)

- **생성은 하루 1회 배치.** 미국 장 마감 후, 한국 시간 아침대(예: KST 06:00)에 실행.
- 조회와 생성은 분리한다. **pull-to-refresh는 절대 Haiku/LLM 파이프라인을 새로 트리거하지 않는다** — 캐시된 결과만 재조회.
- 이미 최신 상태에서 새로고침 시 "이미 최신이에요" 피드백.
- 화면에는 항상 생성 기준 시각을 노출한다 ("7월 18일 06:00 기준").
- **원칙: 매일 열 이유를 만들지 않는다.** 실시간 속보 피드, 새로고침 유도, 배지·카운트다운 등 재방문 강박 유도 장치를 넣지 않는다. (상위 문서 "안심 투자 동반자" 철학과 정합 — 패닉셀 방지가 핵심 목표이므로 습관성 방문 유도 자체가 반(反)목표.)

### 5.1 온보딩 예외

"하루 1회 배치" 원칙은 유지하되, **첫 자산 등록 시점에는 예외적으로 즉시 1회 생성을 트리거**한다. 막 시작한 사용자에게 "내일 아침에 오세요"는 첫인상으로 부적절하기 때문.

- 트리거: 사용자가 첫 보유 종목을 등록한 직후.
- 화면: §3.4의 "온보딩 · 첫 생성 중" 상태 노출 (보유 종목 11개 기준이면 병렬 생성으로 수 초~수십 초 내 완료 예상).
- 생성 실패 시: §3.4의 "로드 실패" 상태로 폴백, 다음날 정기 배치 때 자동 재시도.
- 이 예외 이후로는 다시 하루 1회 배치 리듬으로 복귀 — 온보딩 그 순간에만 적용되는 1회성 예외.

## 6. 조용 상태 원칙 (기존 문서에서 유지)

보유 종목에 24시간 내 뉴스가 없는 경우:

- **셀을 숨기지 않는다.** "N일째 특이사항 없음 · 지켜보고 있어요" 형태로 능동적으로 노출한다.
- 회색 처리·비활성 스타일 금지 — 조용함은 빈 상태가 아니라 **긍정적 정보**(능동 감시의 증거)로 취급한다.
- 문구는 항상 능동형으로 ("지켜보고 있어요"), 수동형 금지 ("소식이 없습니다" 같은 표현 지양).

> 이 원칙은 매크로 배너(§3.1, 없으면 완전히 숨김)와는 다른 처리다. 두 섹션의 "없을 때" 동작이 의도적으로 다르다 — 매크로 배너는 예외적 알림이라 없으면 안 보이는 게 정상이고, 종목 셀은 보유 종목이 존재하는 한 상시 자리를 차지하는 구성요소라 "없음"도 하나의 상태로 명시해야 한다.

## 7. 유지 원칙 — 기존 문서에서 가져온 것

오늘 브레인스토밍에서 다루지 않았지만, 기존 스펙 문서에 있던 내용 중 명시적으로 유지하기로 한 3가지.

### 7.1 개인화 자산 영향 환산

- 종목의 가격 변동을 **내 보유 비중 기준으로 환산해서 보여준다.** 예: "NVDA는 내 자산의 12%, 오늘 -2.1% → 총자산 기준 -0.25%"
- 리스트 셀(간략), 상세 화면 최상단(자세히) 양쪽에 노출.
- 계산은 뉴스 페이로드가 아니라 **보유 정보 + 시세**에서 수행 (뉴스 파이프라인과 무관한 별도 데이터 소스).
- 이게 Yahoo Finance·네이버 금융 등 어떤 뉴스 탭도 못 주는 지점이라는 점에서, §1의 차별점과 함께 이 제품의 핵심 차별화 요소로 취급한다.

### 7.2 업데이트 주기 철학

§5에 통합 반영함.

### 7.3 카피 가드레일 & 조용 상태 원칙

§2.3(헤드라인 톤), §6(조용 상태)에 통합 반영함. 금지 문구 체크리스트:

- ❌ "상승/하락할 것으로 보입니다" (예측)
- ❌ "매수/매도 기회" (권유)
- ❌ "안전합니다" (단언 — 항상 "○일 ○시 기준" 형태로)
- ❌ "놓치지 마세요", "지금 확인하세요" (긴급성 조작)

### 7.4 색·톤 시스템

기존 앱 디자인 시스템 토큰을 그대로 재사용한다(`Color+Hex.swift`) — 새 색 토큰을 만들지 않는다.

| 용도 | 토큰 | 값 |
|---|---|---|
| 상승 | `Color.trendUp` | #0A7A47 (초록, 흰 배경 대비 5.4:1 — 기존 #1ECB81은 2.1:1로 AA 미달이라 디자인 크리틱 후 교체) |
| 하락 | `Color.trendDown` | #F25C5C (빨강) |
| 매크로 배너 강조 | `Color.brand` | #3461FD (파랑) |
| 주의/경고 (일반 UI) | `Color.warning` | #C58B00 (호박) |

**AI판단 섹션은 예외 — `trendDown`(빨강)을 쓰지 않는다.** 기존 `NewsroomDigestDetailView.swift`는 "변동성이 큰 구간" 배지에 `trendDown`을 쓰고 있었는데(§0 경고 참조), 이건 §4.1의 "공포 증폭 금지" 원칙과 충돌한다. 변동성을 언급하더라도 AI판단 섹션 자체는 `Color.brand` 계열의 중립적 틴트를 쓴다 — 내용이 주의를 담고 있어도 색으로 한 번 더 경고하지 않는다.

**조용 로우는 색을 안 쓴다.** §6 원칙대로 회색 처리·비활성 스타일 금지, `textPrimary` 유지.

**매크로 배너**는 `Color.brand` 소프트 틴트 배경 — 관세 같은 이슈가 반드시 나쁜 소식은 아니므로 `danger`/`trendDown` 계열은 쓰지 않는다.
