# iOS 로그인·탭 전환 검증 — 2026-10-04

## 범위

- iOS 클라이언트만 수정했다. 서버 코드와 서버 폴더는 읽거나 수정하지 않았다.
- 제공된 계정으로 배포된 API에 로그인하고, 새 iPhone 17 Pro / iOS 26.1 시뮬레이터에서 검증했다.
- 실제 휴대폰에 설치된 TestFlight 빌드는 직접 실행하지 않았다. 변경 코드는 새 빌드를 업로드해야 TestFlight에 반영된다.
- 비밀번호·토큰·응답 본문은 이 문서와 저장소에 기록하지 않았다.

## 실제 요청·응답

서명을 적용한 시뮬레이터의 로그인 직후 기록이다. 인증이 필요한 GET 요청에는 Bearer 헤더가 포함됐고, 이 실행에서는 401이 관찰되지 않았다.

| 요청 | 결과 |
|---|---|
| `POST /api/auth/login` | HTTP 200, 디코딩 성공. 액세스 토큰 유효기간 1,800초 |
| `GET /api/newsroom` | HTTP 200, 디코딩 성공 |
| `GET /api/newsroom/XLV`, `/XLE`, `/XLF` | 각각 HTTP 200, 디코딩 성공 |
| `GET /api/portfolio` | HTTP 200, 디코딩 성공. 해당 실행에서 약 4초 |
| `GET /api/feeds/policy` | HTTP 200, 디코딩 성공 |
| `GET /api/daily-briefing` | 클라이언트의 8초 대기 제한에 도달해 요청 취소 및 기존 대체 표시 사용. HTTP 응답은 확인하지 못함 |
| `GET /api/holdings` | 클라이언트의 8초 대기 제한에 도달해 요청 취소 및 기존 대체 표시 사용. HTTP 응답은 확인하지 못함 |

별도의 직접 API 확인에서는 로그인·뉴스룸이 HTTP 200이었고, 브리핑·보유종목·포트폴리오는 35초 동안 응답을 받지 못했다. 이후 시뮬레이터 실행에서는 포트폴리오가 성공했으므로 지연은 실행별 차이가 있었다. 응답을 받지 못한 요청을 HTTP 500이나 디코딩 실패로 분류하지 않는다. 서버 지연 원인은 조사하지 않았다.

초기 서명 없는 시뮬레이터 실행에서는 Keychain 세션이 유지되지 않고 인증 헤더가 누락됐다. 서명을 적용한 실행에서는 헤더와 앱 재실행 후 세션 복원이 정상 동작했다. 이 초기 실패만으로 실제 TestFlight에 동일한 문제가 있다고 판단하지 않는다.
