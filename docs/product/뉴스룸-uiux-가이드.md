# 뉴스룸 탭 — UI/UX 작업 가이드

> 작성일 2026-07-12 · Claude Code 작업 참조용
> 상위 문서: `docs/product/안심-product-thesis.md` (제품 철학 전체) — 충돌 시 이 가이드보다 상위 문서가 우선하되, 본 문서가 뉴스룸에 한해 더 구체적이다.

---

## 1. 뉴스룸의 정의 — 한 줄

**오늘탭 = 사실(내 자산에 무슨 일이 있었나) / 뉴스룸 = 이해(그게 왜, 나에게 무슨 의미인가).**

뉴스룸은 "더 많은 뉴스, 더 넓은 뉴스"를 보여주는 탭이 아니다. 네이버 금융·토스증권 뉴스탭과 속보량으로 경쟁하지 않는다. 불안한 장기보유자가 "왜 떨어졌어? 나 괜찮은 거야?"를 확인하러 왔을 때 답을 주는 **이해의 공간**이다.

## 2. 절대 규칙 (Non-negotiable)

1. **매일 열 이유를 만들지 않는다.** 실시간 속보 피드, 새로고침 유도, 데일리 배지 금지.
2. **침묵은 비용이 아니라 자산이다.** 새 소식이 없으면 요약을 만들어내지 않고 "N일째 특이사항 없음"을 보여준다. 이것은 빈 화면이 아니라 능동 감시의 증거(heartbeat)다.
3. **LLM은 통역가다.** 요약은 기사에 있는 사실만 전달한다. 방향 예측, 목표가, "사라/팔아라/버텨라" 류의 행동 권유 문구 금지.
4. **날짜 정직성.** 모든 요약/줄거리에 `generatedAt` 기준 시점을 노출한다 ("7월 12일 08:00 기준").
5. **제거 대상 (기존 코드에서 철거):**
   - `NewsroomNewsFilter.latest` ("실시간 속보" 필터) — 불안 제조 + 습관성 방문 유도
   - `NewsroomHeaderView`의 시세 티커 헤더 (`NewsroomMarketTicker` 스파크라인) — 뉴스룸을 시세창으로 만들고 오늘탭과 역할 중복

## 3. 뉴스 요약 파이프라인 (백엔드 — 어떻게 요약하는가)

iOS는 LLM을 직접 호출하지 않는다. 기존 패턴 유지: **LLM 호출은 백엔드 담당, iOS는 완성된 텍스트만 수신** (`ThemeSignalNarrativeCache.swift` 주석 참조).

### 3.1 수집·클러스터링 (2층 구조)

```
24시간 내 기사 수집 (종목별, 소스: yfinance)
   ↓
[0층] 중복 제거 — 같은 보도자료의 재탕/리라이트 기사 병합
   — "기사 6개"가 실제로는 고유 사실 1~2개인 경우가 대부분
   — 여기서 걸러진 고유 사실 수가 has_news 게이트의 입력이 됨
   ↓
[1층] 시장 공통(매크로) 버킷 분리
   — 금리, CPI, 지수 전반 등 여러 종목에 걸치는 이슈
   — 종목 다이제스트에 중복 배포하지 않고 시장 스토리 1개로만 발행
   ↓
[2층] 종목 고유 버킷
   — 해당 종목에만 해당하는 뉴스 (실적, 제품, 규제 등)
```

이유: 종목 우선 클러스터링만 하면 금리 뉴스가 QQQ·NVDA·AMD 카드에 전부 반복된다.

### 3.2 요약 LLM 출력 스키마 (게이트 내장)

요약과 발행 게이트를 별도 시스템으로 나누지 않는다. 요약 호출 1회의 출력 스키마에 게이트를 포함한다:

```json
{
  "headline": "클러스터 전체를 아우르는 우산 제목 1개",
  "summary": "요약 본문 (2~3문장)",
  "has_news": true,
  "materiality": "high | low",
  "new_facts": ["전날 대비 새로 확인된 사실만 나열"]
}
```

**제목(headline) 가드레일 — 제목은 가장 위험한 LLM 출력이다.** 본문 요약의 어색함은 용인되지만 제목의 오류·과장은 치명적이다:

- 원본 기사에 없는 숫자 금지
- 선정적 동사 금지 (폭락, 폭등, 충격, 비상 등)
- 항상 귀속 형태 사용 ("~발표", "~보도", "~전망(출처)")
- 제목의 모든 주장은 근거 기사 중 최소 1건에서 직접 확인 가능해야 함

**yfinance 주의:** 비공식 스크레이퍼로 상용 배포 시 라이선스 리스크 있음. 프로토타입 용도로 한정하고, 출시 전 정식 뉴스 API 교체를 전제로 소스 레이어를 추상화해둘 것.

- `has_news`: **전날 요약(또는 누적 줄거리) 대비** 새로운 사실이 있는가. 재탕·리라이트 기사만 있으면 false.
- 프롬프트 필수 원칙: **"새로운 것 없음(has_news=false)은 실패가 아니라 정답인 출력"**임을 명시. LLM은 시키면 재탕 기사에서도 그럴싸한 요약을 만들어내므로, 비교 기준(전날 요약)을 프롬프트에 함께 제공해야 한다.
- 금지 출력: 방향 예측, 매매 권유, 요약 대상 기사에 없는 주장.

### 3.3 발행 규칙

```
has_news == true  → 요약 발행, quietDays 리셋
has_news == false → 요약 미발행, quietDays += 1
                    (앱은 "N일째 특이사항 없음" 표시)
```

### 3.4 줄거리(storyline) 레이어 — 2단계 확장

`new_facts`를 종목별로 누적하면 "지금까지의 줄거리"가 된다. 갱신 규칙: `기존 줄거리 + 오늘 new_facts → 갱신된 줄거리` (LLM, 변화 있을 때만 실행). 1차 출시엔 없어도 되지만 스키마에 `storyline` 필드 자리는 미리 잡아둔다.

## 4. 전달 방식 (API 계약 — 어떻게 보내는가)

### 4.1 응답 스키마 (제안)

```json
GET /newsroom/digest?userId={id}

{
  "generatedAt": "2026-07-12T08:00:00+09:00",
  "severity": "calm | watch | alert",
  "marketStory": {
    "headline": "시장 공통 이슈 제목",
    "summary": "…",
    "storyline": "지금까지의 줄거리 (nullable)",
    "updatedAt": "2026-07-11T08:00:00+09:00"
  },
  "caution": {
    "active": false,
    "message": "1~2일 내 변동성이 커질 수 있는 구간이에요 (모델 기준). 이런 구간은 지난 4년간 ○○번 있었고, 대부분 며칠 안에 지나갔어요.",
    "basis": "realized_vol | model_tier"
  },
  "tickerDigests": [
    {
      "ticker": "QQQ",
      "hasNews": true,
      "quietDays": 0,
      "materiality": "high",
      "headline": "우산 제목",
      "summary": "…",
      "newFacts": ["…"],
      "storyline": "… (nullable, 2단계)",
      "articles": [
        { "title": "…", "source": "…", "publishedAt": "…", "url": "…" }
      ]
    },
    {
      "ticker": "AAPL",
      "hasNews": false,
      "quietDays": 3,
      "summary": null,
      "newFacts": [],
      "articles": []
    }
  ]
}
```

핵심 계약 두 가지 — 백엔드와 반드시 합의:
- `hasNews`/`quietDays`가 내려와야 iOS가 "조용" 상태를 그릴 수 있다.
- `severity`는 오늘탭 `TodayBriefingSeverity`(calm/watch/alert)와 **동일한 상태 축**을 쓴다. 뉴스룸이 별도 상태 체계를 만들지 않는다.

### 4.2 iOS 수신 규칙

- DTO: 기존 `PolicyNewsNetworkDTOs.swift` 패턴 (`nonisolated struct … : Decodable, Sendable`, 옵셔널 관대 파싱).
- 캐싱: `ThemeSignalNarrativeCache` 패턴 재사용 — 당일 자정 만료, 메모리+디스크. 다이제스트는 하루 1회 생성물이므로 실시간 폴링 금지.
- `articles[]`는 요약의 **근거 자료**다. 리스트 최상위에 기사 피드를 노출하지 않고, 요약 카드 상세에서 "근거 기사 N건"으로 접근.

### 4.3 업데이트 주기 — 생성과 조회의 분리

서버 부하 문제는 생성과 조회를 분리하면 사라진다. **pull-to-refresh는 LLM 파이프라인을 절대 트리거하지 않는다.**

| | 주기 | 비고 |
|---|---|---|
| 생성 (백엔드 배치) | 하루 1회, 미국 장 마감 후 한국 아침 ~06:00 KST | 사용자의 아침 확인 리듬과 정합 |
| 추가 생성 | severity가 alert인 날 장중 1회 | 예외적 |
| 조회 (클라이언트) | 발행물 GET + ETag/If-None-Match | 변경 없으면 304, 비용 ~0 |

**주기 정직성 UX (필수):**
- 화면에 항상 표기: "7월 12일 06:00 기준 · 다음 업데이트는 내일 아침"
- 이미 최신 상태에서 pull-to-refresh → "이미 최신이에요" 피드백
- 주기를 숨기지 않고 자백하는 것이 새로고침 강박을 없애는 장치다 (날짜 정직성 원칙)

## 5. 화면 구성

### 5.0 레이아웃 원칙 — "피드"가 아니라 "유한한 브리핑"

시각 레퍼런스: **Apple News의 "Today" 탭** (For You 무한 피드 아님). 히어로 카드, 타이포 위계, 카드 그루핑은 참고하되, 무한 스크롤·개인화 피드 회전·배지 등 재방문 유도 메커니즘은 채택 금지.

- 콘텐츠 분량은 의도적으로 유한하다: 내 종목 수 + 시장 스토리 1 + 학습 카드. 게이트 때문에 조용한 날은 더 짧다.
- 페이지 끝에 명시적 종료 마커: "오늘 브리핑은 여기까지예요" — 끝이 있다는 것 자체가 안심 기능이다.
- 카드 크기 차등: materiality high → 히어로 카드, low → 컴팩트 로우. 조용한 종목 → 한 줄 조용 카드 (§5.2).

### 5.1 섹션 순서 (위 → 아래)

| # | 섹션 | 내용 | 상태 의존 |
|---|---|---|---|
| 1 | 상태 브리핑 | calm: 주간 톤 요약 / alert: "오늘 무슨 일이 있었나" + 과거 유사 상황 base rate | `severity` |
| 2 | 시장 공통 스토리 | `marketStory` 카드 1장. 없으면 섹션 숨김 | — |
| 3 | 내 종목 카드 | 종목별: 줄거리 + (hasNews면) 오늘의 요약 / (아니면) 조용 상태 | `hasNews` |
| 4 | 학습 콘텐츠 | 기존 `NewsroomLearningContent` 재사용. 단, 독립 피드가 아니라 위 스토리·요약에 "이걸 이해하려면" 카드로 페어링 | — |

관련성 우선순위(3링): 내 자산 → 내 자산이 속한 테마/섹터 → 시장 전체. 바깥 링 콘텐츠에는 항상 "내 자산과의 연결" 태그를 단다 (`NewsroomRelevanceLevel` 재사용).

### 5.2 종목 카드 상태별 표현

**hasNews == true:**
```
[QQQ]                        7월 12일 08:00 기준
오늘의 요약 2~3문장…
새로 확인된 사실 · 2건        근거 기사 5건 >
```

**hasNews == false (조용 상태) — 디자인 주의:**
```
[AAPL]
3일째 특이사항 없음 · 계속 지켜보고 있어요
```
- 회색 처리/비활성 스타일 금지. 조용함은 실패나 빈 상태가 아니라 **긍정적 정보**다.
- "지켜보고 있어요" 문구로 능동 감시를 전달 (홈 보안 패널 모델).
- 기존 `NewsroomEmptyCard`와 다른 컴포넌트다 — Empty는 "데이터 못 불러옴", 조용은 "불러왔더니 평온함".

### 5.3 색·톤

- severity 색상은 `TodayModels.swift`의 규칙 재사용: calm=액센트 없음, watch=`Color.warning`, alert=`Color.trendDown`. 새 색 도입 금지.
- 디자인 토큰: `DesignSystem/PolSignalTokens.swift`, `AppTheme.swift`만 사용.
- alert 상태에서도 공포 증폭 금지 — 톤은 "무슨 일인지 설명해줄게"이지 "위험!"이 아니다.

### 5.4 상세 화면 — 사용자의 질문 순서대로 배치

다이제스트 카드 탭 시. 순서는 불안한 장기보유자가 뉴스를 클릭하는 실제 이유 순이다:

| # | 사용자의 질문 | 내용 |
|---|---|---|
| ① | "나 괜찮아?" | 내 자산 영향 — 종목 주가 변화 + 내 총자산 기준 환산 ("NVDA는 자산의 12%, 오늘 -2.1% → 총자산 -0.25%"). 숫자와 사실만 |
| ② | "무슨 일이야?" | 우산 제목 + LLM 요약 본문 |
| ③ | "무슨 뜻이야?" | AI 번역 — 사실의 해석과 내 자산과의 연결까지만. 전망·권유 금지 |
| ④ | "근거는?" | 원본 기사 N건 (출처·시간 표기) |

①이 이 제품의 차별점이다 — Apple News도 네이버도 "당신의 자산에서 무슨 의미인지"는 주지 못한다. 자산 영향 계산은 뉴스 페이로드가 아니라 보유 정보 + 시세로 클라이언트/자산 API에서 수행.

### 5.5 모델 주의 문구 (caution) — 노출 규칙

"큰 변동 가능성이 있으니 주의하세요" 류의 모델 기반 문구는 다음 조건을 전부 지킬 때만 노출한다:

1. **수치 비노출.** 확률 숫자는 UI에 절대 표시하지 않는다 (앵커링·공포 유발). 정성 문구 + 근거 자백("모델 기준")만. 숫자는 로그에만.
2. **등급 게이트.** High Confidence 등급 이상만 노출. Normal 등급은 내부용 (5~6거래일마다 오탐 절반의 경고 = 불안 벽지).
3. **침묵의 비대칭.** 모델이 조용해도 "괜찮아요"를 렌더링하지 않는다. 경고 없음 = 문구의 부재. (recall ~68% — 큰 변동의 1/3은 경고 없이 온다)
4. **base rate 페어링 필수.** 경고 단독 노출 금지. 항상 과거 맥락과 함께: "이런 구간은 지난 4년간 ○○번 있었고, 대부분 며칠 안에 지나갔어요." 경고 단독 = 공포, 경고 + 맥락 = 예방접종.
5. **단일 소스.** caution은 뉴스룸이 자체 계산하지 않고 앱 전체 severity 소스에서 읽는다. 뉴스룸은 "주의"인데 오늘탭은 평온이면 신뢰 붕괴.

**출시 순서:**
- **v1: 실현 변동성 트리거** — "오늘 변동성이 컸어요"는 사실이라 위험 0. `caution.basis = "realized_vol"`
- **v2: 모델 등급 트리거** — 하락-only precision 검증(ML 팀 보류 중) 통과 후에만 활성화. `caution.basis = "model_tier"`
- UI 계약은 동일하므로 v1→v2는 백엔드 트리거 교체만으로 전환된다.

### 5.6 LLM 상호작용

- 기존 "1분 요약 / 자세히 분석" 시트(`NewsroomInsightMode`) 패턴 유지.
- 요약 카드에 "이게 무슨 뜻?" 번역 버튼 부착 가능 (thesis §6-1, 위험 0 패턴).
- 상시 채팅 입력창 금지.

## 6. 구현 가이드 (Claude Code 작업 규칙)

### 6.1 아키텍처 패턴 (기존 관례 준수)

```
Features/Newsroom/
  DTO/            ← NewsroomDigestDTOs.swift (신규, §4.1 스키마)
  Models/         ← 화면 모델. DTO → Model 매핑은 Repository에서
  Repositories/   ← Protocol + Live/Mock + Factory 3종 세트 (Today/Signal과 동일 패턴)
  ViewModels/     ← @MainActor ObservableObject
  Views/          ← 화면, Views/Components/ ← 재사용 카드
```

- 신규 Repository: `NewsroomDigestRepositoryProtocol` + `LiveNewsroomDigestRepository` + `MockNewsroomDigestRepository` + Factory.
- 기존 화면을 뒤엎지 말고 additive로. 철거(§2-5)는 별도 커밋으로 분리.

### 6.2 Mock 데이터 요구사항

`MockNewsroomDigestRepository`는 최소 3개 시나리오를 제공해야 한다:

1. **calm + 전 종목 조용** — quietDays 각기 다르게 (1일/3일/12일). 이 화면이 가장 자주 보이는 기본 상태다.
2. **calm + 일부 종목만 뉴스** — hasNews 혼재.
3. **alert** — 상단 브리핑이 "오늘 무슨 일" 모드, materiality=high 다이제스트 포함.

### 6.3 작업 순서 (권장)

1. 철거: 속보 필터·티커 헤더 제거 (`NewsroomView.swift`, `NewsroomHeaderView.swift`)
2. DTO/Model/Repository 신설 + Mock 3종
3. 조용 상태 카드 (5.2) — 가장 자주 보이는 상태부터
4. 종목 다이제스트 카드 + 상세 화면 (§5.4 질문 순서 준수)
5. 상단 상태 브리핑 (severity 연동) + 종료 마커
6. 시장 공통 스토리 카드
7. caution 문구 v1 (실현 변동성 기반, §5.5)
8. 학습 콘텐츠 페어링 재배치

### 6.4 금지 문구 체크리스트 (요약·UI 카피 공통)

## 7. 오늘탭과의 경계 (중복 방지)

| | 오늘탭 하단 뉴스 섹션 | 뉴스룸 |
|---|---|---|
| 역할 | 사실 헤드라인 1~3건 + "더보기" | 요약·줄거리·맥락·학습 |
| 분량 | 한 줄 | 카드·상세 |
