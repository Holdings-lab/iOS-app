## 작업 1 — 전역 텍스트 색 토큰 교정 (최우선)

**파일: `Common/Extension/Color+Hex.swift`**

현재 측정값 (WCAG 대비, 흰 카드 / 캔버스 #F4F6FB 기준):

| 토큰 | 현재 값 | 대비 | 문제 |
|---|---|---|---|
| textSecondary | #8B92A8 | 3.1 / 2.9:1 | 본문 기준(4.5:1) 미달, 캔버스에선 큰글씨 기준(3:1)도 미달 |
| textTertiary | #8B92A8 | 동일 | **secondary와 같은 값 — 토큰 버그.** 위계에 중간 계단이 없음 |
| textQuaternary | #AEB5C6 | 2.1 / 1.9:1 | 장식 전용 수준 |

변경:

```swift
// Before
nonisolated static let textSecondary  = Color(hex: "8B92A8")
nonisolated static let textTertiary   = Color(hex: "8B92A8")
nonisolated static let textQuaternary = Color(hex: "AEB5C6")

// After
nonisolated static let textSecondary  = Color(hex: "475569")  // 7.6:1 — 읽는 보조 텍스트
nonisolated static let textTertiary   = Color(hex: "64748B")  // 4.8:1 — 메타 정보(출처·시간·기준일)
nonisolated static let textQuaternary = Color(hex: "8B92A8")  // 셰브런·구분자 등 장식 전용
```

주의:
- `DesignSystem/PolSignalTokens.swift`의 `PSColor`는 건드리지 않는다 (Signal 플로우 전용 팔레트, 이미 #64748B로 정상).
- 이 토큰은 앱 전역에서 쓰인다. 변경 후 오늘탭·내 자산·온보딩 화면을 육안 확인할 것 — 어두워지는 방향이라 가독성은 좋아지지만, 회색을 "비활성 표현"으로 쓴 곳이 있으면 그 자리만 textQuaternary로 강등한다.

## 작업 2 — 다이제스트 상세: 본문을 '읽기 텍스트'로 승격

**파일: `Features/Newsroom/Views/NewsroomDigestDetailView.swift`**

| 대상 | 현재 | 변경 |
|---|---|---|
| 요약 본문 | `.pretendard(15.5, .regular)` + `textSecondary` + `lineSpacing(6)` | `.pretendard(16, .regular)` + **`textPrimary`** + `lineSpacing(7)` |
| "새로 알려진 내용" 항목 텍스트 | `.pretendard(14, .medium)` + `textSecondary` | `.pretendard(14.5, .medium)` + **`textPrimary`** |
| 근거 기사 제목 | `.pretendard(13.5, .semibold)` | `.pretendard(14, .semibold)` (색 유지) |
| 푸터 자백 | `mutedForeground.opacity(0.3)` | **`textTertiary`** (opacity 제거) — 신뢰 장치이므로 읽혀야 함 |
| 종목 헤더 등락 숫자 | `.pretendard(28, .bold)` | `.pretendard(26, .bold)` — 제목(23)과의 초점 경쟁 완화 |

원칙: 회색(textSecondary 이하)은 메타 정보에만. 사용자가 **읽어야 하는** 문장(요약·새 사실·번역)은 전부 textPrimary.

## 작업 3 — 번역 블록을 단일 컨테이너로 통합

**파일: `Features/Newsroom/Views/Components/NewsroomInlineTranslationBlock.swift`** (+ 호출부 `NewsroomDigestDetailView.swift`)

현재: pill 버튼(brandTintBg)과 번역 본문 박스가 별도 배경의 두 덩어리 → 시각적 소속 불명확, 세로 공간 이중 소모.

변경 구조:

```
[접힘]  ┌──────────────────────────────┐
        │  이게 무슨 뜻인가요?        ⌄ │   ← 카드 1장 = 토글
        └──────────────────────────────┘

[펼침]  ┌──────────────────────────────┐
        │  이게 무슨 뜻인가요?        ⌃ │   ← 같은 카드의 헤더 행 (탭하면 접힘)
        │ ──────────────────────────── │   ← hairline
        │  번역 본문…                   │   ← 같은 카드 내부
        └──────────────────────────────┘
```

- 배경은 하나만 (brandTintBg 유지, 펼침 시에도 동일 배경으로 확장). 내부 본문 별도 배경 금지.
- 번역 본문: `.pretendard(14.5, .medium)` + `textPrimary` + `lineSpacing(6)`.
- 펼침/접힘 애니메이션은 기본 easeInOut 수준, 화려한 모션 금지.
- 로딩 중엔 헤더 행 아래 스켈레톤 2줄 (기존 규칙 유지).

## 작업 4 — 스페이싱 리듬: 그룹 만들기

**파일: `NewsroomDigestDetailView.swift`**

현재 바깥 VStack `spacing: 20` 균일 → 전 섹션이 같은 간격으로 나열되어 그룹이 안 보임.

변경: 균일 spacing을 버리고 그룹 단위로 재배치.

```
종목 헤더
── 32 ──
[기사 블록]           ← 내부 간격 12~14 (제목 ↔ 요약 ↔ 새로 알려진 내용)
── 28 ──
[번역 카드]
── 28 ──
[함께 보면 좋아요]     ← 1장
── 28 ──
[근거 기사]
── 20 ──
[푸터]
```

구현은 바깥 VStack `spacing: 0` + 그룹별 `.padding(.top, …)` 또는 중첩 VStack 중 기존 코드 스타일에 맞는 쪽.

## 작업 5 — 하단 탭바 겹침 해소

**파일: `NewsroomDigestDetailView.swift`**

현재 스크롤 콘텐츠 `.padding(.bottom, 34)` — 플로팅 탭바에 근거 기사 섹션이 깔림.

변경: 콘텐츠 하단 여백을 탭바 높이 + 16으로. 앱에 탭바 높이 상수/safeAreaInset 관례가 이미 있으면 그것을 재사용하고(다른 탭 화면에서 grep), 없으면 `.padding(.bottom, 100)` 수준으로 맞춘 뒤 시뮬레이터로 확인.

## 검증 체크리스트

1. Mock 시나리오 B로 상세 진입 (NVDA) → 스크린샷: 요약·새 사실이 검정 본문으로, 메타만 회색인지
2. 번역 펼침/접힘 — 카드 1장으로 확장·수축하는지, 이중 배경 없는지
3. 최하단 스크롤 — 근거 기사 마지막 행과 푸터가 탭바 위에서 전부 보이는지
4. 시나리오 C(alert) 상세 — 하락 숫자 색상(trendDown)과 새 토큰 조합 확인
5. **전역 회귀**: 오늘탭 / 내 자산 / 뉴스룸 리스트 / 온보딩에서 회색 텍스트 육안 비교 — 비활성 의도였던 곳이 진해졌으면 해당 지점만 textQuaternary로
6. 다크모드 대응이 있다면 동일 토큰의 다크 값도 확인 (현재 hex 고정이면 라이트 전용임을 인지)

## 우선순위

작업 1 → 2 → 3 → 4·5 순. 1·2만으로 체감 개선의 대부분이 나온다. 커밋은 "전역 토큰(1)"과 "상세 화면(2~5)"을 분리할 것 — 회귀 원인 추적을 위해.
